## A1-01 manual GitHub administration required

The connected GitHub integration does not have the Administration permission required to create or change repository rulesets/branch protection. Do **not** mark A1-01 verified until this is applied and tested.

Preferred repository ruleset configuration for `main`:

1. Open the repository on GitHub.
2. Go to **Settings -> Rules -> Rulesets**.
3. Choose **New ruleset -> New branch ruleset**.
4. Name it **Main CI protection** and set enforcement to **Active**.
5. Target the default branch / branch name pattern `main` only.
6. Enable **Restrict deletions**.
7. Enable **Block force pushes**.
8. Enable **Require a pull request before merging**. For a solo-owner repository, do not require a reviewer approval unless another reviewer is actually available.
9. Enable **Require status checks to pass** and select the Codeedge CI check generated by workflow **CI**, job **build**. Enable the option requiring the branch to be up to date before merge if GitHub offers it for the selected rule.
10. Do not add a normal developer bypass that makes failed CI optional. If an owner/admin recovery bypass is configured, reserve it for emergency repository recovery only and keep normal PR merges subject to the required CI check.
11. Save/activate the ruleset.

Verification after configuration:

- open a tiny verification PR against `main`
- while the required `build` check is pending, confirm the normal merge control is blocked
- make the check fail intentionally on that verification PR and confirm normal merge remains blocked
- restore the change, obtain GREEN `build`, and confirm normal merge becomes allowed
- confirm a normal direct push to `main` is rejected
- confirm force-push/deletion are blocked by the ruleset

Only after those observations may A1-01 move from **BLOCKED** to **VERIFIED**.
